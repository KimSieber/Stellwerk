## 2. Entscheidungen (08.11.2026)

| Frage | Entscheidung Kim |
|---|---|
| Umfang v0.5 | „Umschalten“ als Hauptthema, dazu K1–K4 – „damit wir A und B haben“ |
| Hilfsdateien | wie KONZEPT: **Anhang hinten** `name.dpl-<lauf>` (Schattendatei) und `name.bak-<lauf>` (Sicherung) – der Server führt kein halbes Skript aus |
| Ablauf | **zwei Modi:** „Umschalten automatisch“ (Hochladen, Umschalten, Übernehmen in einem Zug, inkl. Löschen der `.bak`) und „Umschalten manuell“ (jede Phase per Knopf). Im Normalfall soll man vom Umschalten nichts mitbekommen – ein Rollback ist nur im Fehlerfall nötig |
| Wartender Lauf | **sperrt die Stufe** (kein Vergleich, keine Übertragung), auch nach Neustart – Ausnahme von „kein Hinweis auf unvollständige Läufe“ (v0.3) |
| Letzter bekannter Stand (FTPS) | wird **beim Umschalten** fortgeschrieben, beim **Rollback** zurückgesetzt |
| Wartungsseite | **nein** – keine Anforderung |
| Versionsnummer | 0.5 |
| „Inhalte prüfen“ | **nur auf Wunsch**, eigener Knopf, **abgesetzt** von „Schnell vergleichen“/„Mit Server vergleichen“ – ein Sonderfall, den man nicht vorsorglich drückt |
| SMB | **eigene Anmeldung** (nicht nur eine eingehängte Freigabe unter `/Volumes`), zusammen mit SFTP – jetzt v0.7 |
| Schritt 3 (Fortsetzen, Reste) | nach v0.6. **Fortsetzen entfällt:** „Wenn was schiefgeht, dann komplett zurück und nochmal neu beginnen.“ Reste erkennen bleibt (v0.6.2) |
| Übergaben im Repository | `docs/intern/` steht jetzt in `.gitignore`; die bisherigen Übergaben bleiben in der Historie (keine Geheimnisse) |

**Von mir festgelegt (bei Schritt 2 genannt, nicht widersprochen):**
- Fehler beim Hochladen → **nie teilweise umschalten**, der Lauf bleibt „hochgeladen“, nur „Abbrechen“.
- Fehler beim Umschalten → **anhalten**, `.bak` bleibt, nur „Rollback“; kein automatischer Rollback (er kann über FTP selbst scheitern).
- Fehler beim Übernehmen → Live-Seite ist richtig, der Lauf gilt als übertragen; Reste bleiben liegen (v0.6.2).
- Abbruch durch den Nutzer beim Hochladen → sofort aufräumen.
- Alte Strecken mit `modus = "umschalten"` gelten als „automatisch“.

## 4. Schritt 1: K1–K3

### 4.1 K1 – Neu vergleichen bei Rückkehr ins Fenster
- Die Streckenansicht hört auf `window` „focus“ und `document` „visibilitychange“.
- Neu verglichen werden Stufen mit Status „fertig“, deren Vergleich älter ist als **`NEU_VERGLEICHEN_NACH_MS` = 60 s**.
- Nicht, wenn das Fenster verdeckt ist, eine Stufe in der Vergleichsansicht offen ist oder gerade verglichen wird. FTPS wie immer ohne Serverkontakt.

### 4.2 K2 – Keine Schreibrechte
- Schreibende FTPS-Befehle (`STOR`, `RNFR/RNTO`, `MKD`, `DELE`, `RMD`, `SITE CHMOD`) gehen über `schreibfehler(e, abs)` bzw. `.am(abs)`.
- `550`/`553` mit „denied“ im Text → **`KeineRechte`**: „Keine Schreibrechte in `<Ordner>` – Serverpfad der Stufe bzw. Rechte am Server prüfen (Server antwortet 550 …)“. Andere Antworten bleiben „Verbindung: Server antwortet …“.

### 4.3 K3 – Wiederholungen der Datenverbindung im Journal
- `mit_datenkanal` zählt Wiederholungen je Thread (`DATEN_WIEDERHOLT`); `ZielVerbindung::hinweis()` liefert nach jeder Operation „Datenverbindung n-mal mit neuem Port wiederholt“.
- `exec` gibt den Hinweis als 5. Argument an das Journal. **Schema 4:** Spalte `journal.hinweis`. Die Streckenansicht zeigt ihn je Schritt (⚠, orange).

## 5. Schritt 2: Umschalten

### 5.1 Kern (`exec::umschalten`)

| Phase | Was geschieht | Bei Fehler |
|---|---|---|
| **Hochladen** (`hochladen`) | Worker-Pool wie „Direkt“ über `SchattenZiel`: Dateien als `name.dpl-<lauf>` (erst Temporärdatei, dann umbenannt), neue Ordner und Rechte gleich (Rechte von Dateien an der Schattendatei). Löschungen kommen nicht vor; der Teilplan wird neu nummeriert, das Journal erhält die Nummern des ganzen Plans | Fehler je Datei; nie umschalten |
| **Umschalten** (`umschalten`) | nur Umbenennen: `Tauschen` (Original → `.bak`, Schatten → Original), neue Datei Schatten → Original, zu löschende Datei → `.bak` | stoppt beim ersten Fehler |
| **Übernehmen** (`uebernehmen`) | `.bak`-Dateien und zu löschende Ordner entfernen | läuft weiter |
| **Rollback** (`zurueckrollen`) | rückwärts: Sicherung zurück (ersetzen), neue Datei bzw. Schattendatei weg, gelöschte Datei zurück, neue Ordner weg (wenn leer) | läuft weiter |
| **Abbrechen** (`abbrechen`) | Schattendateien und neue Ordner weg | läuft weiter |

- **Jede Aktion ist wiederholbar:** `Umbenennen` nur, wenn die Quelle (noch) eine Datei ist; `Tauschen` nur mit vorhandener Schattendatei (Original nur, wenn noch da).
- **Rollback einer neuen Datei** (`NeuZurueck`): Liegt die Schattendatei noch da, wurde nicht umgeschaltet – nur sie verschwindet. Eine **fremde Datei**, die das Umschalten verhindert hat, bleibt unberührt. (Fehler aus Schritt 2a, durch einen Test aufgedeckt.)
- **Verbindung** für Phasen 2/3: bis zu **3 Versuche** (`VERBINDEN_VERSUCHE`), nur bei Kategorie `verbindung`.
- Phasen 2/3 laufen der Reihe nach über **eine** Verbindung.
- `ZielVerbindung` neu: `umbenennen(von, nach, ersetzen)` (ohne `ersetzen` ist ein vorhandenes Ziel ein Fehler „inzwischen vorhanden“), `ist_datei`. FTPS nutzt beim Ersetzen den gelernten Rückfall (`umbenennen_ueberschreibt`).
- Schreibweisen-Wechsel (`bild.jpg` → `Bild.jpg`): Die vorgezogene Löschung steht im Plan vorn und weicht zuerst – funktioniert.
- **Abweichung:** Lokal erhält eine überschriebene Datei die **Rechte der Quelle** (bei „Direkt“ behält sie ihre bisherigen). FTPS unverändert. → Übergabe v0.6.

### 5.2 Datenbank Schema 5

| Änderung | Zweck |
|---|---|
| `journal.hash`, `journal.mtime_ns` | Hash und Zeit der Quelle je hochgeladener Datei – für den letzten bekannten Stand beim späteren Umschalten (auch nach Neustart) |
| Tabelle `manifest_sicherung` | Stand vor dem Umschalten, je Lauf – Rollback stellt ihn wieder her, Übernehmen verwirft ihn |
| `LaufPhase`: `hochgeladen`, `umgeschaltet`, `zurueckgerollt` | `ist_offen()`: hochgeladen/umgeschaltet sperren die Stufe |
| `JournalStatus`: `hochgeladen`, `umgeschaltet`, `zurueckgerollt` | Status je Operation und Phase |

Ältere Datenbanken werden beim Öffnen hochgestuft (Schema 3 → 4 → 5), Inhalt bleibt.

### 5.3 Tauri-Hülle

| Befehl / Teil | Verhalten |
|---|---|
| `plan_erstellen` | Umschalten erlaubt; Vorschau enthält `modus`; gesperrte Stufe → `lauf_offen` |
| `vergleich_starten` | gesperrte Stufe → `lauf_offen` („Auf dieser Stufe wartet ein Lauf auf „Umschalten“/„Übernehmen“ …“) |
| `lauf_starten` | Modus aus der Konfiguration; Umschalten → `umschalten::starten`; Antwort mit `phase` |
| `lauf_weiter(lauf_id, schritt)` | `umschalten` / `uebernehmen` / `rollback` / `abbrechen`; nur in passender Phase (Umschalten nur ohne Hochladefehler, Übernehmen nur nach vollständigem Umschalten); Ziel muss dasselbe sein wie beim Hochladen (`ergebnis.ziel`) |
| Protokoll | `lauf_gestartet`, `hochgeladen`, `umgeschaltet`, `uebernommen`, `zurueckgerollt`, `abgebrochen`, Fehler je Operation |
| Lauf-Ergebnis | Ergebnis des Hochladens + je Phase `{ erledigt, fehler, gestoppt }` |

`ZielEp` bündelt das Ziel als Endpunkt (lokal oder FTPS mit Passwort und Gelerntem) für „Direkt“ und „Umschalten“.

### 5.4 Oberfläche
- **Editor:** Modus „Direkt“, „Umschalten automatisch“, „Umschalten manuell“.
- **Übertragen-Dialog:** Hinweis zum Modus; danach „Hochgeladen als Schattendateien – die Live-Seite ist unverändert …“ bzw. „Umschalten angehalten …“; Knopf **„Weiter in der Streckenansicht“** (kein Neuvergleich der gesperrten Stufe).
- **Streckenansicht:** Karte der gesperrten Stufe orange, mit Stand, Erklärung, Knöpfen (Umschalten/Abbrechen bzw. Übernehmen/Rollback; nach Fehlern nur zurück), Tooltips je Knopf und Rückmeldung nach jedem Schritt. Danach Neuvergleich der Stufe und der folgenden.
- Protokoll: Texte für die neuen Phasen und Journal-Status.

Kims Rückmeldung zum Ablauf (Dialog für Schritt 1, Schritte 2/3 in der Gesamtsicht – „unlogisch“) → **v0.6.1**.

## 6. Schritt 4: Inhalte prüfen (K4)

- Nach einem Erstvergleich kennt Stellwerk bei gleicher Größe nur die Größe → „gleich“ mit Hinweis **„Inhalt nicht geprüft“**.
- **Kern:** `Ftps::inhalte_hashen(pfade, abbruch, fortschritt)` – eine Verbindung, `RETR` je Datei, BLAKE3 beim Lesen (Inhalt geht in `io::sink`), nur lesend. Fehler je Datei (danach neue Verbindung, die Steuerverbindung könnte aus dem Takt sein); Abbruch beendet alles. `VergleichsSitzung::ungeprueft()` liefert die betroffenen Pfade mit Größe.
- **Befehl `inhalte_pruefen(vergleich_id)`** (async, Fortschritt über Kanal, Abbrechen wie ein Vergleich): Hashes in den letzten bekannten Stand. Nur FTPS (sonst `nicht_unterstuetzt`). Nicht protokolliert (am Server wird nichts verändert, E8).
- `VergleichStart.ungeprueft = { anzahl, bytes }`.
- **Oberfläche** (`InhaltePruefen.tsx`): gestricheltes Feld unter dem Hinweis zum Serverstand, nur wenn es ungeprüfte Dateien gibt: „⚠ 37 Dateien mit gleicher Größe – Inhalt nicht geprüft (12,4 MB)“ → „Inhalte prüfen …“ → Bestätigung mit Anzahl und Datenmenge → „Prüfe … 12 von 37“ (abbrechbar) → Neuvergleich ohne Serverkontakt, Meldung „Inhalt von 37 Dateien geprüft“ (ggf. mit nicht lesbaren Dateien).

Abdeckung 100 % (Rust Funktionen/Zeilen, Frontend auch Zweige).

**Erkenntnisse und Techniken:**
- **`?` auf eigener Zeile** (z. B. `})?;` nach einer Closure oder `.lauf(&id)?` in einer Methodenkette) zählt als eigene Zeile mit nie erreichtem Fehlerzweig – je nach Plattform als fehlend. Ergebnis erst binden, dann `let x = x?;`.
- **Rückfälle, die nie eintreten** (`unwrap_or_else(|| …)`), zählen als ungeprüfte Funktion → `unwrap_or_default()` oder `expect`.
- Die Zusammenfassung von `cargo llvm-cov` meldete eine fehlende Zeile, die weder `--text` noch `--lcov` zeigten; gefunden mit `llvm-cov show -show-instantiations` über alle Testprogramme.
- **Farben über eine Pipe:** cargo *und* llvm-cov brauchen `--color always`, die Testprogramme ein zweites `-- --color always`. Die Testprogramme setzen dann hinter „ok“ eine Zeichensatz-Umschaltung – **Linux `\x0f`, Mac `ESC ( B`** – die Auswertung entfernt beide. Lehre: Auswertungen gegen die echte Ausgabe des Macs prüfen (`target/pruefen/rust.log`).
- Messdaten des Macs lassen sich unter Linux nicht auswerten (neuere LLVM-Version des Profilformats).
- Test-Attrappen in `tests/` zählen nicht zur Abdeckung (`unreachable!()` ist dort in Ordnung).
- Der Testserver verträgt gleichzeitige Sitzungen unter Linux nicht immer (TLS „corrupt message“); FTPS-Umschalttests laden mit einer Verbindung hoch, die Phasen verbinden mit bis zu 3 Versuchen.
- Wackelnd unter Last (bekannt, nicht behoben): Tests, in denen zwei kurz nacheinander geschriebene Dateien gleicher Größe dieselbe Änderungszeit bekommen (Linux, grobe Zeitauflösung) – auf dem Mac nicht beobachtet.
