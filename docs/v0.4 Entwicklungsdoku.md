## 2. Entscheidungen zu Beginn von v0.4 (07.11.2026)

| Frage (Übergabe v0.4 Kap. 6/7) | Entscheidung Kim |
|---|---|
| FTPS-Crate, async oder synchron | **`suppaftp` 12 synchron mit `rustls` (ring), Threads wie bisher.** Async bringt bei FTP kein Tempo: Jede Verbindung überträgt eine Datei zur Zeit, das Tempo bestimmen Zahl der Verbindungen und Wartezeit je Datei – in beiden Modellen gleich. |
| Testserver | **Server im Test:** libunftp startet in den Rust-Tests einen FTPS-Server mit eigenem Zertifikat – läuft mit `cargo test` auf Mac und Linux, ohne Docker. |
| Temporärdatei auch bei FTPS | ja (vorsichtige Variante): `.<name>.stw-<lauf>` hochladen, dann `RNFR/RNTO` – nie halbe Dateien am Server |
| Erster Vergleich ohne Manifest | **Größe + Hinweis:** Server einmal lesen; gleiche Größe gilt vorläufig als gleich mit Hinweis „Inhalt nicht geprüft“; Hash nur auf Wunsch (Herunterladen). Das Manifest entsteht mit dem ersten Lauf. |
| Server ohne `MFMT` | Manifest genügt; der Verbindungstest zeigt es an |
| Neu vergleichen bei Rückkehr ins Fenster | **ja**, wenn die Streckenansicht offen ist und der letzte Vergleich älter als 1 Minute ist; FTPS nur gegen das Manifest |
| Ersetzen, wenn der Server beim Umbenennen nicht überschreibt (08.11.) | **je Stufe lernen, nicht vorab testen:** erst `RNTO` versuchen; lehnt der Server ab, alte Datei löschen und sofort umbenennen (kurz fehlt die Datei – im Journal sichtbar). Ergebnis in `stufen_status` (`umbenennen_ueberschreibt`); danach direkt der richtige Weg. Stimmt der gemerkte Wert nicht mehr, greift der Rückfall trotzdem. Ein Schreibtest vorab wäre eine Veränderung am Server. |
| Rechte neuer Dateien bei FTPS (08.11.) | **ohne Stufen-Einstellung keine** – es gilt, was der Server neuen Dateien gibt; nichts wird unbeabsichtigt ausführbar |

**Zur Prüfung vorgelegt (vorsichtige Variante gewählt):**
- Der **bestätigte Zertifikat-Fingerprint** steht in der Strecken-Konfiguration (`ziel.zertifikat`), nicht in der Datenbank (`stufen_status`). Grund: Es ist eine bewusste Einstellung, sichtbar und mit der Strecke sicherbar; die Datenbank hält, was Stellwerk lernt.
- **„Verbindung testen“ liest nur.** `SITE CHMOD` wird deshalb nicht ausprobiert, sondern aus `SITE HELP` gelesen; nennt der Server seine SITE-Befehle nicht, heißt es „unbekannt – wird beim ersten Setzen geprüft“. Ein Schreibtest (Probedatei anlegen und löschen) wäre eine Aktion auf dem Server und müsste protokolliert werden.
- Der Verbindungstest wird **nicht protokolliert** (E8: nur Veränderungen auf Laufwerken/Servern).

## 4. Kern

### 4.1 Endpunkte (`endpoint`) – Paket 1

- **`QuellEndpunkt`** kann nur `oeffnen` (→ `QuellDatei` mit Inhalt, Größe, Änderungszeit, Rechten). `exec` erhält die Quelle ausschließlich so – Schreiben auf die Quelle ist im Typsystem ausgeschlossen (A4, E3).
- **`ZielEndpunkt::verbinden`** liefert eine **`ZielVerbindung`** mit `ordner_anlegen`, `datei_schreiben`, `rechte_setzen`, `datei_loeschen`, `ordner_loeschen`. Lokal ist das ein leichtes Objekt, bei FTPS eine eigene Server-Verbindung.
- **Worker-Pool:** Jeder Worker öffnet bei seinem **ersten Auftrag** eine Verbindung und behält sie. Scheitert der Aufbau, gilt nur dieser Auftrag als fehlgeschlagen; der nächste versucht es erneut. Also höchstens *n* Verbindungen, nie mehr als nötig.
- `kopieren` (blockweise, Abbruch vor jedem Block) und `temp_name` sind gemeinsam für alle Ziele.
- `Lokal` übernimmt das Verhalten aus v0.3 unverändert (alle v0.3-Tests gelten weiter).

### 4.2 FTPS (`endpoint::ftps`) – Paket 2

- **Explizites TLS Pflicht:** `AUTH TLS`, dann `PBSZ 0`/`PROT P` (auch der Datenkanal verschlüsselt). Lehnt der Server `AUTH TLS` ab → „bietet kein TLS an – unverschlüsseltes FTP wird nicht unterstützt“ (E6).
- **Zertifikat:** Prüfung durch das Betriebssystem (`rustls-platform-verifier`, auf macOS die Vertrauenseinstellungen des Systems). Lehnt es ab, gilt das Zertifikat nur, wenn sein **SHA-256** als `ziel.zertifikat` bestätigt ist (Schreibweise egal). Sonst Fehler `zertifikat` **mit Fingerprint** – die Oberfläche bietet „Diesem Zertifikat vertrauen“ an.
- **Immer binär** (`TYPE I`); passiver Modus mit NAT-Umgehung (private Adresse im `PASV` → Adresse der Steuerverbindung).
- **Zeitlimits** 30 s für Aufbau, Steuer- und Datenkanal.
- Fehler: `verbindung` (nicht erreichbar, Name unbekannt, kein TLS, Server-Antworten), `anmeldung` (`530`), `nicht_gefunden` (Serverpfad), `zertifikat`. Das Passwort erscheint in keiner Meldung.
- **Begrüßung vorab prüfen** (`peek`, die Begrüßung bleibt für FTP erhalten): Meldet sich ein SSH-Server → „Hier antwortet ein SFTP-Server (SSH), kein FTP-Server. Für FTPS ist meist Port 21 richtig.“ (so bei manitu auf Port 23); andere Antwort → „Hier antwortet kein FTP-Server (Antwort beginnt mit …). Bitte Server und Port prüfen.“; nichts innerhalb des Zeitlimits → „keine Begrüßung vom Server“; sofort aufgelegt → eigene Meldung.
- **`verbindung_testen`** (liest nur): Begrüßung, `PWD`, Einträge per `NLST` (prüft den TLS-Datenkanal), Fähigkeiten aus `FEAT` (`MLSD` **oder `MLST`** – ProFTPD meldet nur `MLST`, RFC 3659; `MFMT`, `REST STREAM`, `UTF8`) und `SITE HELP` (`CHMOD` ja/nein/unbekannt), Zertifikat mit Fingerprint und ob vom System anerkannt.
- **Geprüft an Kims Server** (manitu, ProFTPD, Port 21, 08.11.2026): explizites TLS 1.3, Zertifikat `*.manitu.net` vom System anerkannt, `MLST`, `MFMT`, `SITE CHMOD`, `REST STREAM`.

### 4.3 FTPS schreiben (`FtpsVerbindung`) – Paket 3

`Ftps` ist ein `ZielEndpunkt`: Jeder Worker erhält eine eigene angemeldete Verbindung; ob `MFMT` geht, steht je Verbindung aus `FEAT` fest. Alle Pfade werden **absolut** gebildet (Serverpfad der Stufe + relativer Pfad) – das Arbeitsverzeichnis spielt keine Rolle.

- **Ordner anlegen:** `MKD`; ist er inzwischen da (`CWD` gelingt), in Ordnung.
- **Datei schreiben:** Neu, aber am Server inzwischen vorhanden (`SIZE` gelingt) → Fehler „bitte neu vergleichen“. Sonst `STOR` nach `.<name>.stw-<lauf>` (blockweise, Abbruch je Block, BLAKE3 mitgerechnet), bei Fähigkeit `MFMT` mit der Zeit der Quelle (UTC; scheitert es, bleibt die Serverzeit – das Manifest kennt die richtige), dann `RNFR/RNTO` (siehe Entscheidung oben). Bei jedem Fehler wird die Temporärdatei entfernt.
- **Nach `ABOR`** (Abbruch während des Hochladens) ist die Steuerverbindung nicht mehr verlässlich (viele Server antworten zweimal: 426, 226) – sie wird vor dem Aufräumen durch eine neue ersetzt.
- **Rechte:** `SITE CHMOD <oktal> <pfad>` – nur als eigene Operation aus dem Plan (Stufen-Einstellung).
- **Datei löschen:** `DELE`; scheitert es: inzwischen ein Ordner → Fehler; schon weg → in Ordnung; sonst Fehler des Servers.
- **Ordner löschen:** `RMD` (nur leer); schon weg → in Ordnung.
- Gelerntes (`umbenennen_ueberschreibt`) gilt für alle Verbindungen eines `Ftps` und wird mit `mit_umbenennen_ueberschreibt` vorgegeben bzw. mit `umbenennen_ueberschreibt()` abgefragt – das Speichern in `stufen_status` geschieht mit Paket 4 im Befehl.
- `ZielVerbindung::datei_schreiben` liefert jetzt `Geschrieben { bytes, hash }` – der Hash ist die Grundlage des Manifests (Paket 4); `exec` verwendet vorerst nur die Bytes.

### 4.4 Datenbank Schema 2 (`store`) – Paket 3

| Tabelle | Inhalt |
|---|---|
| `manifest` | je Strecke/Stufe/Pfad: `ist_ordner`, `groesse`, `hash` (BLAKE3, fehlt nach einem Erstvergleich nur mit Größe), `mtime_ms` (Zeit der Quelle beim Übertragen), `lauf_id` |
| `stufen_status` | Gelerntes je Stufe: `schluessel`, `wert`, `aktualisiert` |

- **Hochstufen:** Eine Datenbank aus v0.3 (Schema 1) erhält beim Öffnen nur die neuen Tabellen – Läufe, Journal und Protokoll bleiben. Neuere Schemata werden weiterhin nicht angefasst.
- `manifest_setzen` (einfügen/ersetzen), `manifest_entfernen` (Pfad **samt Inhalt**, exakter Präfix – `LIKE` wäre in SQLite unabhängig von Groß/Klein und träfe `Web/` beim Löschen von `web/`), `manifest_ersetzen` (ganz oder gar nicht, für Erstvergleich/Vollabgleich), `manifest` (nach Pfad sortiert); `status_setzen`, `status`.
- Beschädigte Einträge (Hash nicht 32 Bytes, ungültiger Pfad) werden als Fehler gemeldet.

### 4.5 Vergleich mit FTPS-Ziel – Paket 4a

- **`Ftps::auflisten`** liest den Serverpfad rekursiv (eine Verbindung): `MLSD`, wenn der Server `MLSD`/`MLST` meldet, sonst `LIST` (Unix-Format; Zeit dort nicht verwendet). Ignorierte Ordner werden nicht betreten. Wurzel nicht lesbar → Fehler (sonst sähe alles „neu“ aus); nicht lesbare Unterordner und Zeilen → Lesefehler. Namen mit `/` oder `..` → Lesefehler. Ein Dateiname mit Zeilenumbruch zerfällt im Listing in zwei Zeilen (Lesefehler + falscher Name – selten, bekannt).
- **`scan::aus_liste`**: Regeln wie beim lokalen Scan auf eine fertige Liste (Manifest oder Server).
- **`stufe_vergleichen_entfernt(…, EntfernterStand)`**: `Manifest` (ohne Serverkontakt) oder `Server { ftps, manifest }`. Ziel-Einträge kommen immer aus dem (ggf. abgeglichenen) Manifest; mit Server zusätzlich `neues_manifest` zum Speichern.
- **`manifest_abgleichen`**: Server-Stand + altes Manifest – gleiche Art und Größe behalten Hash und Zeit, sonst unbekannt; was der Server nicht mehr hat, fällt heraus; sortiert.
- **Vergleich** (`diff`): Steht der Hash des Ziels schon im Eintrag (Manifest), wird nur die Quelle gelesen. Gleiche Größe und Zeit → gleich ohne Lesen. Ist der Inhalt unbekannt → „gleich“ mit Hinweis **`InhaltNichtGeprueft`** (Kims Entscheidung „Größe + Hinweis“). `InhaltPruefer::hash_ziel` liefert dafür `Option`.
- **Abweichung von der Entscheidung „Manifest entsteht mit dem ersten Lauf“:** Es entsteht schon beim ersten Einlesen des Servers (ohne Hashes). Sonst fehlten unveränderte Dateien nach dem ersten Lauf im Manifest und erschienen als „neu“. – **Zur Prüfung vorgelegt.**
- **Schema 3:** Spalte `mtime_ms` → `mtime_ns` (Zeit wie beim Scan in ns; sonst gälte eine unveränderte Datei nie als „gleiche Zeit“). Datenbanken mit Schema 2 werden umbenannt, Inhalt bleibt.
- **`exec`**: Die Journal-Rückmeldung enthält je erledigter Datei `Uebertragen { geschrieben: {bytes, hash}, quelle_mtime_ns }` – Grundlage für das Fortschreiben des Manifests (Schritt 3).

## 6. Frontend

**„Verbindung testen“** erscheint im Editor unter jedem FTPS-Ziel (nicht bei der Quelle):
- Knopf (gesperrt ohne Server, während des Tests „Teste Verbindung …“). Ein eingegebenes, noch nicht gespeichertes Passwort wird verwendet, sonst das hinterlegte.
- **Erfolg** (grün): „✓ Verbunden mit …“, Serverpfad und Einträge, Begrüßung, und eine Übersicht: Zertifikat (vom System / bestätigter Fingerprint), MLSD, MFMT („nein – Vergleich über das Manifest“), SITE CHMOD (ja/nein/unbekannt), REST.
- **Zertifikat nicht anerkannt** (rot): Meldung, SHA-256, Hinweis zur Prüfung (Kundenmenü des Hosters), Knopf **„Diesem Zertifikat vertrauen“** → setzt `zertifikat` am Ziel; gespeichert wird mit der Strecke. Ein bestätigtes Zertifikat steht unter dem Knopf, mit „Bestätigung entfernen“.
- Andere Fehler als Text. Das Ergebnis gilt nur für die getesteten Angaben – ändert sich ein Feld, verschwindet es.

Abdeckung 100 % (Rust Funktionen/Zeilen, Frontend auch Zweige). Gegenproben zu allen neuen Teilen (50 eingebaute Fehler, jeder macht Tests rot).

**Testserver** (`crates/stellwerk-testserver`): libunftp auf `127.0.0.1` mit zufälligem Port; Zertifikat selbstsigniert oder von einer Test-CA (die der Prüfung als zusätzliche Wurzel übergeben wird); Schalter für TLS 1.3 (libunftp: sonst nur 1.2), Klartext-Server, `SITE HELP` (Antwort 200/214), `SITE CHMOD`, ein Speicher-Backend, das **`RNTO` auf vorhandene Dateien ablehnt**, und gesperrte Dateinamen (weder löschen noch umbenennen). Der Ordner des Servers liegt lokal – Tests prüfen das Ergebnis direkt dort. libunftp meldet `MLSD`, aber **kein `MFMT`**: Dass `MFMT` gesendet und ein Fehler übergangen wird, ist getestet (`mfmt_erzwingen`); dass die Zeit wirklich ankommt, zeigt erst Kims Server (ProFTPD kann `MFMT`).

**Erkenntnisse und Techniken:**
- **Zwei Übersetzungen des Kerns:** Funktionen, die ein Unit-Test (im Modul) aufruft, werden für die Abdeckung getrennt von den Integrationstests gezählt. Sie müssen deshalb im Unit-Test **vollständig** durchlaufen werden (alle Arme), sonst bleiben unsichtbare Zeilen offen. Was nur Integrationstests brauchen, gehört nicht in Unit-Tests.
- **Closures für Fehlerumwandlung** vermeiden, wo der Fehler nie eintritt (zählen als ungeprüfte Funktion) – benannte Funktionen (`ftp_fehler`, `anmeldefehler`, `tls_einrichtung`) verwenden.
- **Async-Befehle von Tauri:** Der Makro-Code für ein ungültiges **letztes** Argument zählt als eigene Funktion → Test mit falschem Typ im letzten Argument.
- **TLS-Fehler bei suppaftp** kommen als Verbindungsfehler (Handshake erst beim ersten Lesen). Ob das Zertifikat schuld ist, sagt deshalb der Zustand der eigenen Prüfung, nicht die Fehlerart – und dieser wird vor jedem Versuch zurückgesetzt (Test mit Zwischenstecker: erst echter Server, dann Abbruch nach `AUTH TLS`).
- **Zwischenstecker in Tests** muss beim Auflegen einer Seite auch die andere trennen, sonst wartet der Client bis zum Zeitlimit.
- **Testserver nacheinander:** libunftp bindet passive Ports mit `SO_REUSEADDR` – parallel laufende Server/Sitzungen störten sich (TLS „corrupt message“, ca. 10 %). Server eines Testprogramms laufen jetzt nacheinander (wiedereintrittsfähige Sperre je Thread: ein Test darf mehrere Server halten). Zusätzlich ist die **serverseitige TLS-Sitzungswiederaufnahme im Testserver abgeschaltet** – sie vertrug in libunftp keine gleichzeitigen Sitzungen (danach 0 von 50 Fehlschlägen). Stellwerk selbst nutzt die Wiederaufnahme weiter (ProFTPD verlangt sie für Datenverbindungen meist); ob mehrere Verbindungen am echten Server sauber laufen, zeigt der erste echte Lauf.
- **Wackelnder Abbruch-Test** deckte einen echten Fehler auf: Nach `ABOR` war die Steuerverbindung aus dem Takt, das Aufräumen scheiterte gelegentlich. Seit dem Ersetzen der Verbindung 15-mal hintereinander grün.
- macOS-Check per `cargo check --target aarch64-apple-darwin` ist mit `ring` in Linux nicht möglich (braucht die Apple-Werkzeuge); `rustls-platform-verifier` bietet auf macOS dieselben Konstruktoren.
