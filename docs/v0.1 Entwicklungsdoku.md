Stand: 07.11.2026 · Version 0.1 (Commits v0.1a … „Standardregeln im Editor“) · Bezug: [KONZEPT.md](KONZEPT.md), [ARCHITEKTUR.md](ARCHITEKTUR.md)

Diese Dokumentation beschreibt, **was in v0.1 tatsächlich gebaut wurde**, wie es aufgebaut ist, wie man damit arbeitet und wo die Umsetzung vom Architekturentwurf abweicht.

## 2. Entwicklungsumgebung

Voraussetzungen (macOS): Rust stable, Node.js ≥ 20, Xcode Command Line Tools.
Für die Abdeckungsmessung zusätzlich einmalig:

```bash
rustup component add llvm-tools-preview
cargo install cargo-llvm-cov
```

## 4. Kern (`stellwerk-core`)

### 4.1 Modell

- **`Strecke`** (`id`, `name`, `version`, `regeln`, `stufen`) – eine TOML-Datei je Strecke, Dateiname = `id`.
- **`Stufe`**: `quelle: Quelle`, `ziel: Endpunkt`, `modus` (direkt | umschalten), `rechte`, `nur_online`, `regeln`.
- **`Quelle`**: `lokal { pfad }` · `stufe { stufe }` (Ziel einer Vorstufe) · `ftps` (nur noch aus Kompatibilität lesbar, Validierungsfehler).
- **`Endpunkt`** (Ziel): `lokal { pfad }` · `ftps { host, port, pfad, benutzer, tls, konto_ref }`. `tls` kennt nur `explizit` – Klartext-FTP ist im Typ nicht darstellbar.
- **`RelPath`**: relativer Pfad, NFC-normalisiert, `/`-getrennt, ohne `..`. `RelPath::new` für Text aus der Konfiguration; `RelPath::aus_komponenten` für Dateisystempfade (ein Backslash ist **Teil des Namens**, kein Trenner).
- **`Eintrag`** (Scan-Ergebnis): Art (Datei/Ordner/Symlink), Größe, `mtime_ns`, `nur_online`, `hash` (lazy), Warnungen.
- **`Dateimodus`**: Oktal als Text („755“), 0–777.
- Alle Strukturen mit `deny_unknown_fields`: Tippfehler und z. B. ein Feld `passwort` in der TOML werden abgelehnt.

### 4.2 Konfiguration und Prüfung

- `ConfigStore`: `global_laden` (fehlt die Datei → Standardwerte, **ohne** zu schreiben), `strecken_liste` (defekte Dateien verdecken die übrigen nicht), `strecke_laden` (Kennung muss zum Dateinamen passen), `strecke_anlegen` (**überschreibt nie** → Fehler `vorhanden`), `strecke_speichern`, `strecke_loeschen`. Schreiben atomar über `.toml.tmp` + Umbenennen.
- `validiere_strecke` – reine Prüfung ohne Dateizugriff, liefert `Problem { schwere, ort, meldung }`; `ort` adressiert das Feld (z. B. `stufen[1].ziel.pfad`) und wird in der Oberfläche am Feld angezeigt.
- `pruefe_ordner` – prüft, ob lokale Ordner existieren (liest nur die Dateiart). Wird in den Befehlen `strecke_pruefen`, `strecke_anlegen`, `strecke_speichern` und `strecken_liste` angewendet, **nicht** im `ConfigStore` (der bleibt ohne Dateisystemannahmen testbar).
- **Einbahn-Prüfung (E3):** Eine Stufe darf nie in ihre eigene Quelle und nie in die Quelle einer **früheren** Stufe schreiben (Vergleich lexikalisch, ohne Groß-/Kleinschreibung, NFC). Das Ziel einer Stufe darf Quelle einer **späteren** Stufe sein – das ist die Kette. Leere Pfade werden übergangen („Pfad fehlt“ genügt).

### 4.3 Regel-Engine (`rules`)

- `RegelWerk::uebersicht(global, strecke, stufe)` liefert alle Regeln in Auswertungsreihenfolge mit Herkunft und ggf. `abgeschaltet` (Schalter | Strecke | Stufe).
- `RegelWerk::fuer_stufe` kompiliert die wirksamen Regeln; ungültige Muster/Ersatzquellen → `Validierung` mit Ort.
- Auswertung wie gitignore: **letzte passende Regel gewinnt** (Global, Strecke, Stufe; innerhalb der Ebene in Listenreihenfolge) → tiefere Ebene schlägt höhere. `!muster` hebt auf. Ordnermuster (`logs/`) gelten auch für den Inhalt. Muster werden NFC-normalisiert.
- Hinweis: Das macOS-Ordnersymbol heißt in gitignore-Syntax `Icon[\r]` – ein abschließendes `\r` würde abgeschnitten.

### 4.4 Scan (`scan`)

- `scan_lokal(wurzel, regeln, abbruch, fortschritt)`: sortiert, folgt keinen Symlinks, erfasst leere Ordner, NFC.
- „Ignorieren“ wirkt hier: Der ignorierte Eintrag selbst wird erfasst (graue Anzeige), ein ignorierter Ordner aber nicht durchlaufen.
- Warnungen: Symlink, „nur online“ (macOS `SF_DATALESS`), Dropbox-Konfliktkopie, Groß-/Klein-Kollision; Unicode-Doppelungen als Fehler.
- Lesefehler einzelner Einträge werden gesammelt, nicht abgebrochen. Abbruch über `AtomicBool`.
- `hash_datei` – BLAKE3.

### 4.5 Vergleich (`diff`)

`vergleiche(quelle, ziel, regeln, optionen, inhalt, abbruch)` → `Vergleich { eintraege, zusammenfassung }`.

- Status: `neu`, `geaendert`, `loeschen`, `gleich`, `geschuetzt`, `ignoriert`, `konflikt`.
- „Geändert“: Größe → Größe+Zeit gleich = gleich (ohne Lesen) → sonst BLAKE3. Option `inhalt_immer_pruefen`. Dateien „nur online“ werden **nie** gehasht (würde Download auslösen).
- Regeln: Ignorieren/Schützen fassen das Ziel nie an; Nur anlegen legt nur Fehlendes an, sonst geschützt; Ersetzen durch nimmt den Inhalt der Ersatzdatei (auch wenn diese selbst ignoriert ist), fehlt sie → Konflikt.
- Konflikte: Datei ↔ Ordner, Symlinks (immer, auch beidseitig), fehlende Ersatzdatei, Lesefehler. Inhalt unterhalb eines Konflikts wird nicht vorausgewählt.
- Ordner nur am Ziel mit bleibendem Inhalt (geschützt/ignoriert/abgewählt) → geschützt mit Hinweis „enthält Bleibendes“.
- `Bild.jpg` neu / `bild.jpg` zu löschen → beidseitiger Hinweis (Reihenfolge Löschen vor Anlegen muss der Plan sicherstellen).
- Die Hash-Quelle ist austauschbar (`InhaltPruefer`; lokal: `LokalerInhalt`, später Manifest).

### 4.6 Passwörter (`secrets`)

- `Tresor`-Schnittstelle (`setzen`, `lesen`, `entfernen`, `vorhanden`); `SpeicherTresor` für Tests.
- Interner Eintragsname `stellwerk:<strecke>:<stufe>`, Dienst `de.sieber-bw.stellwerk`. Den Namen vergibt Stellwerk selbst; der Editor gleicht ihn bei jeder Änderung an (`kontenAngleichen`).
- macOS-Anbindung in `src-tauri/src/schluesselbund.rs` (`keyring` mit `apple-native`); auf anderen Systemen fällt die App auf den Speicher-Tresor zurück.

### 4.7 Fehler

`StellwerkError` mit `kategorie()`: `konfiguration`, `validierung`, `nicht_gefunden`, `vorhanden`, `kein_verzeichnis`, `schluesselbund`, `abbruch`, `io`. Das Frontend erhält `{ kategorie, meldung, probleme? }`.

## 5. Tauri-Hülle

### 5.1 Befehle

| Befehl | Zweck |
|---|---|
| `konfig_ort` | Pfad des Konfigurationsordners |
| `strecken_liste` | Startseite: Strecken mit Stufen-Kurzform und Prüfmeldungen (inkl. Ordnerprüfung) |
| `globale_regeln` | globale Standardregeln für den Editor |
| `strecke_laden` | eine Strecke |
| `strecke_pruefen` | Validierung + Ordnerprüfung, schreibt nichts |
| `strecke_anlegen` | neu anlegen, überschreibt nie |
| `strecke_speichern` | speichern (nur ohne Fehler) |
| `strecke_loeschen` | Konfiguration und zugehörige Passwörter entfernen – nie Dateien |
| `ist_ordner` | für Drag-and-drop |
| `passwort_speichern` / `passwort_vorhanden` / `passwort_entfernen` | Schlüsselbund; das Passwort kommt nie zurück |

Registrierung zentral in `befehle()` (`lib.rs`) – dieselbe Funktion nutzen die Tests mit der Mock-Laufzeit.

### 5.2 Menü, Plugins, Rechte

- Eigenes deutsches App-Menü (`start.rs`): „Über Stellwerk“ sendet das Ereignis `menue_ueber`; Bearbeiten-Menü für ⌘C/⌘V in Eingabefeldern.
- Plugins: `tauri-plugin-dialog` (Ordnerauswahl), `tauri-plugin-opener` (Links).
- Capabilities: `core:default`, `dialog:allow-open`, `opener:allow-open-url` nur für `https://*.sieber-bw.de` und `mailto:`. Kein Dateisystemzugriff aus dem Frontend.

## 6. Frontend

- **React 19 + TypeScript + Vite**, Server-State mit **TanStack Query**. (Zustand ist eingeplant, wurde noch nicht gebraucht.)
- Navigation ohne Router: `App` hält `{ art: "liste" } | { art: "editor", id? }`.
- **Editor-Prinzipien:**
  - Jede Änderung → `strecke_pruefen` (vorherige Meldungen bleiben stehen, bis die neue Prüfung da ist).
  - Meldungen erscheinen am Feld über `ProblemeKontext` (Abgleich über `ort`) und gesammelt oben mit lesbarem Ort (`ortLesbar`).
  - Speichern nur ohne Fehler; Knöpfe und Meldungen in einem festen Kopfbereich.
  - Rückfrage bei ungespeicherten Änderungen und vor dem Löschen.
  - Kennung folgt dem Namen, bis sie von Hand geändert wird; nach dem ersten Speichern fest.
  - Neue Stufe übernimmt den Zielordner der Vorstufe als **lokalen Quellpfad** (kein Verweis).
  - FTPS nur als Ziel; Passwortfeld verdeckt; Passwörter werden erst **nach** erfolgreichem Speichern der Strecke in den Schlüsselbund geschrieben.
- **Drag-and-drop** (`useOrdnerAblage`): übernommen aus PaperTrail Compare – `data-drop-target` je Ordnerfeld, Y-Versatz je Ziehvorgang kalibriert, Hervorhebung „bereit/aktiv“. Rust prüft per `ist_ordner`; Meldung bei Datei bzw. mehreren Objekten direkt am Feld.
- „Über Stellwerk“ nach Vorbild Mailwerk (Icon, Version aus `tauri.conf.json`, © 2026 Kim Sieber, Stuttgart, Stellwerk@Sieber-BW.de, stellwerk.sieber-bw.de).

## 7. Tests

**Vorgabe:** Jede Funktion und jede Funktionsstrecke ist durch einen automatischen Test abgedeckt. Die Abdeckungsgrenze ist hart hinterlegt (100 % Funktionen und Zeilen in Rust; 100 % Anweisungen, Zweige, Funktionen, Zeilen im Frontend).

| Ebene | Werkzeug | Umfang v0.1 |
|---|---|---|
| Kern | `cargo test`, Temp-Verzeichnisse (`tempfile`), `filetime` | 132 Tests |
| Tauri-Befehle | `tauri::test` (Mock-Laufzeit, echte IPC) | 16 Tests |
| Frontend | Vitest, Testing Library, `@tauri-apps/api/mocks` | 135 Tests |

**Ausgenommen** von der Abdeckungsmessung (nur in der laufenden App prüfbar): `src-tauri/src/main.rs`, `start.rs`, `schluesselbund.rs`. Diese Dateien enthalten nur Verdrahtung.

**Testtechniken, die sich bewährt haben:**
- E/A-Fehler ohne Rechte-Tricks erzeugen (Datei statt Ordner und umgekehrt), damit Tests auch als root und auf macOS gleich laufen.
- Unlesbarer Pfad: Baum über PATH_MAX, aufgebaut durch Umbenennen von unten nach oben (`tests/scan.rs`).
- Plattformspezifisches (Groß-/Klein-Kollision, Unicode-Doppelung, Nicht-UTF-8-Namen) als reine Funktion herauslösen und direkt testen.
- Frontend: `rustAttrappe({ befehl: antwort })` bildet die Rust-Seite nach (inkl. Ereignisse); `ablageSenden()` simuliert Drag-and-drop; `Zustand` hält Werte gesteuerter Bausteine.
- **Gegenprobe:** Nach neuen Tests gezielt Fehler einbauen und prüfen, dass Tests rot werden.

## 8. Abweichungen vom Architekturentwurf

| Entwurf | Umsetzung v0.1 | Grund |
|---|---|---|
| Typen per `specta`/`tauri-specta` generiert | von Hand in `src/api.ts` | wenige Befehle; nachziehen, wenn die Zahl wächst |
| Async-Traits `SourceEndpoint`/`TargetEndpoint` | noch nicht vorhanden; Scan als Funktion `scan_lokal` | kommen mit Planen/Ausführen (Schreibseite) |
| Englische Kern-Typen (`Entry`, `EntryKind`) | deutsche Namen (`Eintrag`, `EintragArt`) | einheitlich mit Strecke/Stufe |
| `konto_ref` sichtbar in der Konfiguration bearbeitbar | intern vergeben, im Editor ausgeblendet | Verwechslung mit dem Passwort |
| FTPS als Quelle möglich | nur noch Ziel | Einbahn: nie vom Server herunterladen |
| Ordner-Existenz Teil der Validierung | eigene Funktion `pruefe_ordner` | Validierung bleibt ohne Dateizugriff |
| Protokoll von Konfigurationsänderungen (E8) | noch nicht | kommt mit SQLite |

## 9. Bekannte Einschränkungen

- „Ersetzen durch“: Liegt die Zieldatei (z. B. `config.php`) weder in der Quelle noch im Ziel, wird sie nicht aus der Ersatzdatei angelegt.
- Sortierung nach Bytes: Umlaute erscheinen nach „z“ (für die Vergleichsansicht ggf. anpassen).
- Erkennung deutscher Dropbox-Konfliktkopien nicht an echten Dateinamen verifiziert.
- Musterregeln für Dateirechte nur in der TOML-Datei, nicht im Editor.
- Globale Standardregeln (`config.toml`) nur per Datei bearbeitbar.
- Im Über-Dialog fehlt die Liste der Open-Source-Lizenzen.
- Speichern aus dem Editor erzeugt die TOML-Datei neu – Kommentare aus Handbearbeitung gehen verloren.
