Stand: 09.11.2026 · Version **0.7.2 abgeschlossen** (Samba-Freigaben, SFTP-Server – beide als Quelle und Ziel) · Bezug: [KONZEPT.md](KONZEPT.md), [ARCHITEKTUR.md](ARCHITEKTUR.md), [v0.6 Entwicklungsdoku](v0.6%20Entwicklungsdoku.md), [v0.5](v0.5%20Entwicklungsdoku.md), [v0.4](v0.4%20Entwicklungsdoku.md), [v0.3](v0.3%20Entwicklungsdoku.md), [v0.2](v0.2%20Entwicklungsdoku.md), [v0.1](v0.1%20Entwicklungsdoku.md), [Anwenderdoku Regeln](Anwenderdoku%20Regeln.md)

Diese Dokumentation beschreibt, **was in v0.7 hinzukommt**: zwei neue Arten von Endpunkten. Stellwerk spricht jetzt **Samba-Freigaben** direkt an (ohne sie im Finder zu verbinden) und **SFTP-Server** (SSH-Dateiübertragung) – jeweils als Quelle und als Ziel, mit eigener Anmeldung über den Schlüsselbund.

## 2. Entscheidungen (09.11.2026)

| Frage | Entscheidung Kim |
|---|---|
| Samba-Zugriff | **direkt über das Netz** (Raspberry Pi `smb://192.168.1.11/manitu`, Benutzer `manitu`), nicht über ein im Finder eingehängtes Laufwerk |
| SFTP | **umsetzen**, als offener Standard und Ergänzung zu FTPS; zuerst Passwort (0.7.2a), dann SSH-Schlüssel (0.7.2b) |
| Passwort / Passphrase | Eingabefeld in der Maske, Ablage **im macOS-Schlüsselbund** wie bei FTPS |
| Host-Schlüssel | beim ersten Kontakt **bewusst bestätigen**; Fingerabdruck (`SHA256:…`) wird in der Strecke gespeichert; `known_hosts` wird nicht verwendet |
| Rust-Bibliothek SFTP | **`ssh2`** (libssh2, synchron, `vendored-openssl`) – nach Prüfung, warum `russh` nicht mit `smb` zusammen baut (Kap. 5.1) |
| SFTP-Testserver | eigenes Programm **außerhalb des Workspace** mit aktuellem `russh` |
| manitu | gleicher Host und Benutzer für SFTP (Port 23) und FTPS (Port 21); Kim legt einen **eigenen FTP-Benutzer für Stellwerk** an (`ftp200043143`) und stellt Strecken auf SFTP mit Passwort um |
| SSH-Benutzer bei manitu | **nein** – ein SSH-Benutzer darf meist auch Befehle ausführen; für reine Dateiübertragung zu viel Recht. SSH-Schlüssel trotzdem fertig bauen, für spätere Server |
| Leerzeichen am Rand | Server und Benutzer verlieren sie **schon im Dialog** (beim Kopieren mitgenommen) |
| Streckenfilter, App-Bau | auf **v0.8** verschoben |

**Von mir festgelegt (genannt, nicht widersprochen):**
- SFTP mit **2 festen Verbindungen** (wie FTPS), Rechte und Zeit per `setstat`, Umbenennen mit Überschreiben – wo der Server das ablehnt – als Löschen + Umbenennen.
- Ziel-Server werden wie bei FTPS gegen den **letzten bekannten Stand** verglichen; „Server lesen“ und „Inhalte prüfen“ gelten für beide Protokolle.
- **Überschneidung** zweier Server-Endpunkte: gleicher Host und Benutzer, Pfade überschneiden sich. Der Port zählt nur bei gleichem Protokoll – FTPS und SFTP erreichen beim selben Hoster dieselben Dateien über verschiedene Ports.
- Samba: **keine Unix-Rechte** (Warnung, wenn Rechte gesetzt sind).
- Ändern sich Server oder Port, **verfällt** der bestätigte Host-Schlüssel.

## 3. Projektstruktur – neu und geändert

```
crates/stellwerk-core/src/
  endpoint/smb.rs        Samba-Freigabe: lesen, schreiben, Verbindung testen (crate `smb`, synchron)
  endpoint/sftp.rs       SFTP: Anmeldung (Passwort/Schlüssel), Host-Schlüssel, Quelle mit Verbindungspool, Ziel
  endpoint/mod.rs        Trait `ServerLesen` – gemeinsam für FTPS und SFTP
  ansicht/ablauf.rs      Vergleich vom Server für beide Protokolle (`server_kennung`)
  model/strecke.rs       `SmbEndpunkt`, `SftpEndpunkt` (Quelle und Endpunkt)
  config/validate.rs     Prüfungen für SMB und SFTP, Überschneidung über Protokolle hinweg
  error.rs               `HostSchluessel { meldung, fingerprint }` (Kategorie `host_schluessel`)
crates/stellwerk-testserver/src/
  smb.rs                 startet ein unprivilegiertes `smbd` (Samba) je Test
  sftp.rs                baut und startet den SFTP-Testserver; Testschlüssel per `ssh-keygen`
werkzeuge/sftp-testserver/   eigenes Cargo-Projekt (eigene Cargo.lock), im Workspace ausgeschlossen
src-tauri/src/commands.rs    `ServerEp` (FTPS|SFTP), `smb_verbindung_testen`, `sftp_verbindung_testen`, `sftp_zugang`
src/editor/                  Felder für Samba-Freigabe und SFTP-Server, Verbindungstests
src/system.ts                `schluesselWaehlen` (Dateidialog, startet in ~/.ssh)
```

## 4. v0.7.1 – Samba-Freigaben

- **Adresse wie im Finder:** `smb://host[:port]/freigabe/ordner` in einem Feld; beim Tippen in Server, Port, Freigabe und Ordner zerlegt (auch `%20` aus dem Finder). Meldungen zu allen Teilen stehen unter der Adresse.
- **Bibliothek:** crate `smb` (reines Rust, SMB 2/3), synchrone Variante – passt zum synchronen Kern.
- **Verbindung testen:** meldet an, liest den Ordner, zeigt die Anzahl der Einträge – verändert nichts.
- **Rechte:** Freigaben kennen keine Unix-Rechte → Warnung an der Stufe, Rechte werden nicht gesetzt.

## 5. v0.7.2 – SFTP-Server

### 5.1 Warum `ssh2` statt `russh`

Ein Cargo-Workspace hat **eine** `Cargo.lock` und damit je Bibliothek nur eine Version pro verträglichem Bereich. `smb` 0.12 legt über `sspi` die Vorabversion `curve25519-dalek =5.0.0-rc.1` fest (macOS); aktuelle `russh`-Versionen brauchen eine andere. `russh` 0.54/0.55 bauen zwar mit `smb` zusammen, haben aber bekannte Sicherheitslücken (behoben erst ab 0.58/0.61/0.63.1). Daher **`ssh2`** im Kern (libssh2, synchron, OpenSSL eingebaut) und der **Testserver als eigenes Projekt** mit aktuellem `russh` (0.65).

### 5.2 Host-Schlüssel

- Fingerabdruck wie bei OpenSSH: `SHA256:` + Base64 ohne Auffüllung.
- Ohne bestätigten Schlüssel verbindet Stellwerk nicht: Fehler `host_schluessel` mit dem Fingerabdruck → im Editor „Host-Schlüssel bestätigen“, danach sofort erneuter Test.
- Meldet ein bestätigter Server einen **anderen** Schlüssel: Warnung „Der Host-Schlüssel hat sich geändert“ – kann ein Serverwechsel sein, aber auch ein Angriff; übernommen wird nur nach ausdrücklicher Bestätigung.

### 5.3 Kern und Hülle

- `Sftp` (Ziel) und `SftpQuelle` (Quelle, Pool mit einer Sitzung je Worker).
- Gemeinsamer Trait **`ServerLesen`** für FTPS und SFTP; Vergleich vom Server, letzter bekannter Stand, „Inhalte prüfen“, Umschalten und Server → Server laufen für beide Protokolle über denselben Weg.
- In der App bündelt **`ServerEp { Ftps, Sftp }`** die Server-Ziele; Meldungstexte nennen „Server (FTPS/SFTP)“.
- Leerzeichen am Rand von Server und Benutzer entfernt der **Editor** (FTPS, SFTP, Samba) – sie führten zu „Name nicht auflösbar“.

### 5.4 Anmeldung per SSH-Schlüssel (v0.7.2b) – ⚠️ ungetestet am echten Server

- In der Strecke steht nur der **Pfad** zum privaten Schlüssel (`schluessel`, `~/` erlaubt), nie der Schlüssel selbst; im Schlüsselbund steht dessen **Passphrase** (darf fehlen).
- Editor: Auswahl „Anmeldung“ – Passwort oder SSH-Schlüssel; Pfad tippen oder per Dialog wählen; das Passwortfeld heißt dann „Passphrase“.
- Verständliche Fehler: Datei fehlt · Passphrase falsch oder Format unbekannt · Server kennt den Schlüssel (oder Benutzer) nicht.
- **Geprüft nur gegen den eigenen Testserver** (Ed25519 mit und ohne Passphrase, OpenSSH-Format). Bei manitu lassen sich Schlüssel nur für SSH-Benutzer hinterlegen, nicht für FTP-Benutzer – deshalb dort bewusst nicht eingesetzt (Kap. 2). Beim ersten echten Einsatz genau hinsehen.

## 6. Testserver

| Protokoll | Server | Voraussetzung |
|---|---|---|
| FTPS | eingebauter `stellwerk-testserver` (libunftp) | – |
| Samba | `smbd` unprivilegiert je Test, eigene Prozessgruppe | macOS: `brew install samba` (`samba-dot-org-smbd`); Linux: Paket `samba` |
| SFTP | `werkzeuge/sftp-testserver` (russh), reicht den SFTP-Kanal an `sftp-server` von OpenSSH weiter | macOS: `/usr/libexec/sftp-server` (System); Linux: `openssh-sftp-server`; `ssh-keygen` für die Testschlüssel |

- Der SFTP-Testserver wird beim ersten Test **einmal gebaut** (eigene `Cargo.lock`, eigenes `target`); `STELLWERK_SFTP_TESTSERVER` kann auf ein fertiges Programm zeigen. Er schreibt `PORT=` und `FINGERPRINT=` und endet, wenn die Standardeingabe schließt.
- Abgelehnte Anmeldungen verzögert er nicht (sonst je 1 s).

Abdeckung 100 % (Rust Funktionen/Zeilen, Frontend auch Zweige).

**Erkenntnisse und Techniken:**
- **`smbd` in der Prüfung:** Ohne eigene Prozessgruppe beendete `smbd` beim Aufräumen den ganzen `npm run pruefen` („zsh: terminated“). Lösung: `process_group(0)` + `--no-process-group` + `stdin(null)` – ein Lesen vom Terminal aus einer Hintergrundgruppe ließ `smbd` sonst sofort enden.
- **macOS-Samba:** ACLs, DOS-Attribute und erweiterte Attribute in der Test-Konfiguration ausschalten, sonst verweigert `smbd` das Anlegen von Ordnern.
- **Rechte-Tests als root** (Claudes Linux-Umgebung) schlagen immer fehl – dort als unprivilegierter Benutzer laufen lassen; auf dem Mac grün.
- **Abdeckung von Fehlerwegen:** Fehler über kleine Hilfsfunktionen (`mit_ort`, `fehler`, `schluessel_fehler`) führen statt über Closures – jede Übersetzung einzeln per Unit-Test.
- **Tauri-Befehle:** Der generierte Pfad für ungültige Argumente zählt als eigene Funktion – je Befehl ein Test mit falschen Argumenten.
- **Regionen** (feiner als Zeilen) müssen nicht 100 % erreichen: `?`-Fehlerwege und vom Compiler erzeugter Code lassen sich oft nicht gezielt auslösen.
- **Plattenplatz** in Claudes Umgebung: `target/llvm-cov-target` und `target/debug` wachsen auf > 25 GB – rechtzeitig löschen.
